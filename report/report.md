## 一、实验目的

本实验围绕物理内存的发现、初始化和分配展开，完整链路为：

```
pmm_init() -> init_pmm_manager() -> page_init() -> init_memmap() -> alloc_pages()/free_pages()
```

主要目的：

1. 理解物理地址、虚拟地址、物理页号与 `struct Page` 页描述符之间的关系；
2. 从设备树（DTB）读取可用物理内存范围，实现 `page_init()` 建立页描述符数组；
3. 读懂 First-Fit 连续页分配算法的初始化、分配、回收与合并流程；
4. 参考 `default_pmm.c` 自行设计并实现 Best-Fit 分配器，并在 `init_pmm_manager()` 中切换为默认管理器；
5. 通过 `make grade` 验证 Page Init 和 Best-Fit 两项现有测试覆盖的功能。

### 实验整体逻辑

本实验先解决“哪些物理页可以使用”，再解决“怎样选择和回收这些页”。设备树提供 RAM 范围，`page_init()` 建立页面描述并排除内核及管理数据的占用，分配器再维护空闲块、处理请求并合并回收块。只有先保证初始可用范围正确，后续分配算法才有可靠的管理对象。

页表与页分配器承担不同职责：页表描述虚拟地址映射到哪里，分配器决定哪些物理页可交给调用者。建立地址映射并不意味着对应物理页一定空闲，分配出物理页也不等于已经为它建立了新的映射。

## 三、page_init() 的实现

### 3.1 内存探测与空闲区建立

`page_init()` 在 `kern/mm/pmm.c` 中完成物理内存的探测与组织。

函数首先通过 `get_memory_base()` 与 `get_memory_size()` 从设备树解析出可用物理内存的基址与大小；若设备树中没有合法的 memory 节点，则直接 `panic()` 终止启动。本机 QEMU virt 平台探测到的结果是基址 `0x80000000`、大小 `0x8000000`（128MB，结束于 `0x87ffffff`）。

拿到内存范围后，设置虚拟地址与物理地址的偏移量 `va_pa_offset = PHYSICAL_MEMORY_OFFSET`，并计算总页号 `npage = PPN(mem_base + mem_size)`。这里 `npage` 是从物理地址 0 开始编号的页号上限，其中 `nbase = PPN(mem_base)`，`npage - nbase` 才是这段 128MB 实际拥有的页数。本机上 `npage = 557056`、`nbase = 524288`，二者相减正好 32768 页。

页描述符数组 `pages` 的位置是关键约束：它必须紧跟在内核镜像末尾、按 4KB 对齐，且数组自身占用的物理页绝不能进入空闲区。实现上取链接符号 `end`（bss 段结束的虚拟地址），用 `ROUNDUP((uintptr_t)end, PGSIZE)` 对齐后作为 `pages` 的虚拟地址。本机 `end = 0xffffffffc0206078`，对齐后 `pages` 位于 `0xffffffffc0207000`。随后把全部 `npage - nbase` 个描述符的标志位置为 `PageReserved`，表示这些页默认不参与分配。

接下来计算真正交给分配器管理的空闲内存起点：从 `pages` 数组末尾开始，即 `PADDR(pages + (npage - nbase))`，再按 4KB 对齐得到 `freemem_pa`。若该起点之后还有完整可用页，则调用当前 `pmm_manager` 的 `init_memmap(pa2page(freemem_pa), nr_free)`，把这一段连续空闲页注册进空闲链表。本机空闲区为 `0x80347000 ~ 0x88000000`，共 31929 页。

运行日志关键行：

```
(THU.CST) os is loading ...
memory management: best_fit_pmm_manager
physical memory: base=0x0000000080000000, size=0x0000000008000000 (128 MB)
npage = 557056, nbase = 524288, pages (va) = 0xffffffffc0207000
free memory: 0x0000000080347000 ~ 0x0000000088000000, 31929 pages
check_alloc_page() succeeded!
```

### 3.2 地址、页号与描述符的关系

| 概念 | 含义 | 本实验中的对应关系 |
| --- | --- | --- |
| 物理地址 | CPU 物理地址空间中的位置 | `page2pa(page)` 返回描述符所对应页的物理地址 |
| 虚拟地址 | 分页环境下内核使用的地址 | 内核直接映射区通过固定偏移与物理地址对应 |
| 物理页号 | 按页大小对物理地址编号 | `PPN(pa)` 相当于去掉 12 位页内偏移 |
| 页描述符地址 | 管理某个物理页的元数据所在位置 | `pages[i]` 对应物理页号 `nbase + i` |

`pages` 是 `struct Page *`，因此 `pages + 页数` 已按结构体大小移动；若先转换为字节地址，才需要再乘 `sizeof(struct Page)`。描述符数组本身也占用 RAM，所以不能把“内核镜像之后的所有页面”直接当成空闲页。

内存按页管理还涉及边界对齐：可用起点向上取整，终点向下取整，排除不完整页面。`PageReserved` 表示页面不能交给普通分配；`PageProperty` 表示空闲块首页，首页的 `property` 记录该块页数。单页状态、块大小和空闲页总数共同描述分配器状态，不能互相替代。

## 四、First-Fit 分配器的理解（任务一思考题）

First-Fit 实现在 `kern/mm/default_pmm.c`。内部状态是一个按物理地址升序排列的空闲双向链表 `free_list`，加一个空闲页数计数 `nr_free`；每个 `struct Page` 的 `property` 字段只在"连续空闲块的首页"上有效，记录该块一共连续多少页。

**初始化空闲页**：`default_init` 仅把链表置空、计数清零；`default_init_memmap` 把一段连续物理页的首地址描述符作为块首，设置 `property = n`、清除 `PageReserved`、引用计数清零，再按地址序挂入空闲链表，`nr_free += n`。

**分配连续物理页**：`default_alloc_pages(n)` 从链表头顺序扫描，找第一个 `property >= n` 的块。若该块正好 n 页则摘下；若比 n 大，就从块首切出 n 页分配，剩余部分作为新的块首（`property -= n`）留在链表中。一旦遇到第一个够大的块就立即切分，不继续往后找，因此叫首次适应。

**回收页面并合并相邻空闲块**：`default_free_pages(base, n)` 先把这 n 页的标志位清成空闲、引用计数清零，再按地址序插回空闲链表。插入后做两次相邻合并：往前看，若前一个块的末尾正好挨着回收块开头（`page2pa(prev) + prev->property * PGSIZE == page2pa(base)`），就把 n 并到前块 `property`；往后看，若回收块末尾正好挨着后块，就把后块页数并过来并把后块从链表摘除。本次回收使 `nr_free` 增加 `n`，相邻块合并只改变链表组织，不应再次增加空闲页总数。

**First-Fit 的改进空间**：空闲块较多时，从链表头线性查找的开销会上升。可以利用辅助索引加快候选块定位，也可以采用从上次位置继续查找的 Next-Fit 策略，但后者已经改变了原本从头查找的选择规则。回收时正确合并物理相邻块有助于缓解外部碎片；若改用伙伴系统，则需要另外权衡二次幂块管理带来的内部碎片。

## 五、Best-Fit 分配器的实现（任务二）

Best-Fit 实现在 `kern/mm/best_fit_pmm.c`，结构与 First-Fit 平行：同样维护地址有序的空闲双向链表和 `nr_free`，`property` 语义相同。差异只在分配策略。

`best_fit_alloc_pages(n)` 遍历整个空闲链表，在所有 `property >= n` 的块中挑选 `property` 最小的那一个。该策略优先使用大小接近请求的块，尽量保留较大的连续空闲块，但不保证长期碎片最少。选中块后与 First-Fit 一样处理：整 n 页则摘下，多出部分分裂为新块首插回链表。`best_fit_free_pages` 的回收合并流程与 First-Fit 完全一致，都是按地址序插入并向前后两个方向合并。

实现完成后在 `pmm.c` 的 `init_pmm_manager()` 中切换为 `pmm_manager = &best_fit_pmm_manager;`，内核启动日志中的 `memory management: best_fit_pmm_manager` 确认切换生效。

测试函数 `best_fit_check` 故意在场内同时放一块 1 页紧块和一块 2 页松块，先申请 1 页、再申请 2 页。若分配器真的选"最小满足块"，第一次就选中 1 页紧块，第二次才命中 2 页松块——这项检查验证该场景下的最小满足块选择行为。

**Best-Fit 的改进空间**：每次全表扫描的时间复杂度为 O(空闲块数)。可使用按大小组织的平衡树等结构加快最小满足块查找，同时维护地址关系以支持合并。Best-Fit 可能形成难以满足较大连续请求的小块，即外部碎片；但本实验以整页为最小单位，一页残块仍可用于单页请求。若采用超额分配整块的策略，还需记录实际分配大小并与释放接口配套，不能直接忽略多分配的页面。

### 两种策略的理论比较

| 比较项 | First-Fit | Best-Fit |
| --- | --- | --- |
| 选块规则 | 选择链表中第一个足够大的块 | 选择所有候选中最小的满足块 |
| 当前链表实现的查找 | 最坏扫描整个链表，找到即可结束 | 遍历链表比较候选块大小 |
| 碎片特点 | 取决于请求序列、块位置和回收情况 | 可能保留较大块，也可能积累小残块 |
| 共同要求 | 准确维护页面状态、空闲计数、分裂与合并 | 同左 |

外部碎片是总空闲页数足够，但缺少满足请求的连续页区间。因此，`nr_free >= n` 只是分配 `n` 个连续页的必要条件，不是成功的充分条件。

## 六、扩展思考题：OS 如何获取可用物理内存范围

如果操作系统无法提前知道硬件的可用物理内存范围，通用做法是依赖引导固件提供的硬件描述。本实验中 OpenSBI 作为 M-mode 固件，在跳转到内核之前会把一块设备树（Device Tree Blob, DTB）的物理地址通过 a1 寄存器传给 S-mode 内核；内核启动代码把这个地址保存到 `boot_dtb`，`dtb.c` 提供的 `get_memory_base()` 与 `get_memory_size()` 就是从 DTB 的 `/memory` 节点解析出 `reg` 属性中的基地址和大小。一般系统还需要结合保留内存和设备地址信息，区分可用 RAM 与不可分配区域。本实验中的解析代码主要读取 memory 节点的 `reg`，固件、内核和描述符数组的排除依据当前平台布局完成，不能等同于已完整解析所有 DTB 保留区。

在没有 DTB 的平台上，替代办法包括：编译时硬编码已知机器的内存映射表（RISC-V virt 平台的 128MB@0x80000000 就是约定）、运行时逐段探测（按页向候选地址写入再回读，能通的视为 RAM，但慢且危险）、或者由引导协议（Linux Boot Protocol、EFI）把内存映射表作为启动参数传给内核。本实验采用的就是 OpenSBI + DTB 这条标准路径。

## 八、实验中遇到的问题

本机使用新版 QEMU 11.1.2，引导阶段出现两个与课程旧环境不同的问题。

第一，在所用固件与通用 loader 配置下，内核镜像已被加载，但下一阶段入口交接未正常完成，日志中 OpenSBI 横幅之后没有任何内核输出，CPU 停在 OpenSBI 内部循环。通过 QEMU 的 `-d in_asm,cpu` 指令日志确认内核入口 `0x80200000` 始终未被执行。解决：改用官方 OpenSBI v1.9 的 `fw_jump` 固件，其跳转地址在编译时固定为 `0x80200000`，不依赖 QEMU 的 fw_dynamic 机制。

第二，从 Bare 切换到 Sv39 后，取指立即受到分页映射约束，而启动页表原本只有高地址内核映射，CPU 在物理地址处继续取指会立刻缺页。解决：在 `boot_page_table_sv39` 中补充 VPN[2]=2 的 1GB 恒等映射（虚拟 `0x80000000-0xbfffffff` 恒等映射到物理 `0x80000000-0xbfffffff`），让切换 satp 后到跳虚拟地址之间的几条指令能正常取指。

两处适配只影响引导流程，不改变 page_init 与 Best-Fit 的实验逻辑。

## 九、实验总结与理论认识

### 9.1 与操作系统原理的联系

| 实验知识点 | 对应原理 | 理解与联系 |
| --- | --- | --- |
| 设备树和内存范围 | 硬件描述与资源发现 | 固件提供 RAM 信息，OS 根据运行环境建立自己的资源管理结构 |
| `struct Page` 与空闲链表 | 页框管理与管理开销 | 管理物理内存需要额外元数据，描述符占用空间也必须纳入规划 |
| 分裂与相邻块合并 | 连续分配与外部碎片 | 分裂满足当前请求，合并恢复较大的连续区间，二者共同影响后续分配能力 |
| 管理器函数指针 | 机制与策略分离 | `pmm_manager` 统一接口，First-Fit 与 Best-Fit 提供不同的选块策略 |
| Sv39 页表与地址偏移 | 地址翻译与虚拟内存 | 页表决定地址映射，分配器决定页面归属，两类状态需要协调但不能混为一谈 |

### 9.2 本实验尚未系统展开的内容

本实验主要围绕启动阶段的物理页管理，没有系统展开用户进程调度、按需分页、页面置换、交换空间、完整的进程地址空间隔离，以及多核或中断并发条件下的内存分配同步。页级管理也不等同于内核小对象分配，后者还需要处理对象尺寸、对象池与页内空间利用等问题。

### 9.3 AI 协作开发的认识

使用 AI 辅助操作系统开发时，需要先明确接口、数据结构和状态约束。例如，物理地址与虚拟地址不能混用，块大小只能在约定的描述符上解释，分配与释放必须保持空闲页计数一致。提示词应提供这些真实上下文，再提出需要实现的行为。

理解算法与理解工程接口同样重要：知道 Best-Fit 要选择最小满足块，还需要说明块如何拆分、剩余部分如何回链，以及回收时如何合并。将需求按这些行为组织，有助于检查生成内容是否真正符合工程约定。

### 9.4 实验收获

本实验将物理内存管理分成了资源发现、元数据初始化和分配策略三个层次。通过这一划分，可以解释为什么初始内存范围、保留区和描述符布局必须先正确，分配器才能在可靠基础上工作；也能认识到，同样的管理接口可以承载不同算法，算法选择需要结合查找开销、连续分配需求和碎片情况进行权衡。
